# ChatGPT 回答粘贴

## 项目功能

这是一个思源笔记插件。把 ChatGPT 的整条回答粘贴到思源正文时，标题、列表、表格和代码块会按 Markdown 排版，回答中的图表也可以随正文一起保存。

- **保存 SVG 图片**。将完整的 SVG 源码、`svg` 代码块或单独一行的 `data:image/svg+xml` 地址直接粘贴为思源本地图片，适合保存架构图、流程图和思维导图。
- **编辑 Mermaid 图表**。剪贴板含有源码时，插件会插入可编辑的思源图表块。只有完整 SVG 预览时，则保存为静态图片。
- **一次粘贴多张图**。图表按原有顺序插入正文。遇到网页复制后丢图的情况，还可以使用配套的 Chrome 或 Edge 扩展复制图文。

## 安装步骤

适用于思源笔记 **3.8.12 及以上版本**的桌面端和桌面浏览器界面。

1. 下载插件安装包 [siyuan-chatgpt-markdown.zip](https://github.com/ZTaer/siyuan-chatgpt-markdown/raw/refs/heads/main/dist/siyuan-chatgpt-markdown.zip)。
2. 在思源中打开 **设置 → 集市 → 已下载**，点击本地安装按钮，选择刚下载的 ZIP 文件。
3. 在已下载的插件列表中找到 **ChatGPT 回答粘贴**，打开启用开关。

也可以手动安装。将 ZIP 解压到思源工作空间的 `data/plugins/siyuan-chatgpt-markdown/`，确认该目录下直接包含 `plugin.json` 和 `index.js`，然后在集市中启用插件。

## ChatGPT记忆答案输出规范

**首次使用插件前，请先把下面整段规范复制并发送给 ChatGPT，再提出你的问题。** 如果换到尚未收到这份规范的对话，请先在那里发送一次。

````markdown
请记住以下「通用 AI 答案输出规范 V2.0」，并在后续回答中遵循。

## 通用 AI 答案输出规范 V2.0

### 一、总体回答原则

- 保证回答的准确性、专业性、易读性、实用性和美观性。
- 根据问题的性质和复杂程度，自主决定回答的篇幅、深度及表达方式。
- 简单问题简洁回答，复杂问题系统化讲解。
- 保持内容层次清晰、逻辑连贯、重点突出。
- 避免无意义的重复、过度解释和不必要的内容扩展。
- 根据内容自主选择最合适的表达与可视化方案。
- 不为了可视化而可视化。
- 兼顾内容的复制、保存、编辑及长期维护。

### 二、Markdown 排版规范

| 内容类型 | 输出规范 |
| --- | --- |
| 一级内容标题 | 使用 `##` |
| 二级内容标题 | 使用 `###` |
| 三级内容标题 | 使用 `####` |
| 正文 | 标准 Markdown |
| 重点内容 | 使用加粗标记 |
| 引用内容 | 标准 Markdown 引用语法 |
| 专业术语 | 根据需要采用中英文结合 |
| 对比分析 | 标准 Markdown 表格 |
| 分类说明 | 表格或结构化列表 |
| 数学公式 | LaTeX |
| 程序代码 | 对应语言的标准代码块 |
| 终端命令 | 对应 Shell 语言代码块 |
| 配置文件 | 对应语言代码块 |
| 参考资料 | 可靠来源及原始链接 |

不使用 Markdown 一级标题 `#`，所有内容标题从 `##` 开始。

根据内容合理使用标题、段落、列表、表格和分隔线，不进行过度排版。

### 三、可视化总体策略

采用 **SVG 优先、其他可视化方式按需补充** 的策略。

不再根据可视化的简单或复杂程度决定是否使用 SVG。凡是确有静态可视化需求，并且 SVG 能够有效表达的内容，均优先采用 SVG 源码方案。

降低 ChatGPT 原生可视化、原生卡片及文案式可视化的使用频率。

只有当 SVG 无法有效表达所需效果，或者其他可视化形式明显更适合时，才选择其他方案。

不使用 Mermaid，包括 Mermaid 流程图、思维导图、时序图、类图等所有类型，相关需求统一由 SVG 替代。

| 原生卡片 | 降低使用频率 | 必要的特殊信息展示 |
| 文案可视化 | 按需使用 | 重点内容、结构化表达 |

### 五、可视化选择逻辑

1. 判断内容是否真正需要可视化。
2. 如果普通文字或 Markdown 表格已经能够清晰表达，则不额外绘图。
3. 如果需要静态可视化，优先采用 SVG。
4. 如果需要动态模拟、参数调整或用户操作，则采用交互式可视化。
5. 如果涉及数据分析，根据数据特征选择合适的统计图表。
6. 如果涉及真实物体、视觉参考、艺术创作或图片编辑，则正常使用图片能力。
7. 只有 SVG 无法有效表达所需效果，或者其他形式明显更合适时，才使用原生可视化等替代方案。
8. 避免使用多种可视化方式重复表达同一个知识点。

### 六、SVG 专属输出规范

所有 SVG 图表必须遵循统一格式，以兼容思源笔记及其他笔记软件的自定义识别和渲染组件。

| 规范项目 | 具体要求 |
| --- | --- |
| 图表标题 | 固定使用 `> SVG图: 具体标题` |
| 标题位置 | SVG 源码代码块正上方 |
| 标题数量 | 每张 SVG 独立对应一个标题 |
| 标题标点 | 英文半角冒号，后面保留一个空格 |
| 代码块语言 | svg |
| 源码格式 | 标准 SVG/XML |
| 源码完整性 | 必须能够独立渲染 |
| XML 命名空间 | 必须包含 |
| viewBox | 必须包含 |
| 图像预览 | 不输出 |
| 额外源码标题 | 不添加 |
| 外部资源 | 不依赖 |
| JavaScript | 不依赖 |
| 动态模板语法 | 不使用 |

每张 SVG 图表只输出以下两个部分：

1. 标准 Markdown 引用标题。
2. 紧随其后的完整 SVG 源码代码块。

标准标题格式：

`> SVG图: 具体标题`

不额外生成同一张 SVG 的图像预览。

不添加“SVG 源码：”等重复说明文字。

使用标准 SVG/XML 属性与语法，确保源码可以脱离原始聊天环境独立渲染。

不使用依赖特定聊天界面、前端框架或动态运行环境的模板语法。

### 九、复制与兼容性规范

- 正文、标题、表格及代码尽量采用标准 Markdown。

- 避免不必要的专业术语和复杂表达。
- 根据实际问题灵活选择概念解释、原理分析、流程说明、案例、优缺点、使用场景及总结等内容结构。
````

## 粘贴回答到思源

在 ChatGPT 复制整条回答，在思源文档正文按 **Ctrl+V**（macOS 用 **⌘V**）。标题、加粗、列表、表格和代码由思源解析，图表随正文插入。需要编辑图表时，优先复制带语言标记的源码。

## 复制多图回答

如果整条复制时出现“缺少 Mermaid 源码”，在 Chrome 或 Edge 的扩展管理页打开开发者模式，点击 **加载已解压的扩展程序**，选中配套的 `browser-helper` 文件夹，然后刷新已打开的 ChatGPT 网页。

点击目标回答下方的 **复制**，回思源按 **Ctrl+V**。遇到带 Mermaid 预览的回答，扩展在网页上读取这条回答，将绘图路径、箭头和标签一并写入剪贴板的 HTML 格式。纯文本应用收到的是回答的可见文字。按住 Shift 点击复制可使用网页原来的复制方式。

如果网页的复制按钮发生变化，也可以在目标回答里选中几个字，再点浏览器工具栏里的 **复制 ChatGPT 图文到思源**。没有选区时，该按钮复制最后一条回答。

从图表菜单切换到源码视图，点击代码块的复制按钮，可得到可编辑的 Mermaid 源码。也可以一次复制含多个 Mermaid 围栏的 Markdown。插件支持剪贴板中的 `text/markdown`、HTML 代码块和可读取的代码视图。只有预览图时，保留静态图片。具体的图表语法由所用思源版本内置的 Mermaid 渲染。

一条回答可以混排流程图、时序图、类图、状态图、ER 图、甘特图和思维导图。带 `mermaid` 标记的代码块直接交给思源渲染，标题、主题和节点名称都可以变化。剪贴板同时带有源码和对应预览时，插件按文档顺序保留各图的源码，也保留穿插在正文中的其他图片。嵌套在 Markdown 教程代码块里的示例围栏保持原样。

**修复已有缺图**：在缺图提示左侧点击块标，选择 **用 Mermaid 源码修复此图…**，粘贴该图的源码，点 **修复并记住**。操作保留原块 ID。在有章节标题且图型可识别时，插件将章节、图型、完整标签和源码存到当前工作空间，以便再次粘贴时复用。若这些条件对应多个不同的已校对版本，插件会保留提示，供手动选择源码。

旧版的 `mermaid-repairs.json` 精确匹配继续生效。对于带样式参照的校对记录，单独复制图时可忽略 ChatGPT 新生成的编号及选择器中的 Markdown 转义。整篇复制时还能按章节、图型和完整标签匹配，适应主题或配色变化。直接复制 Mermaid 源码或 SVG 不依赖校对记录。

| 剪贴板里有的内容 | 粘贴到思源后的结果 |
| --- | --- |
| Mermaid 源码 | 可编辑的 Mermaid 图表块。可识别带语言标记的代码块及常见的无标记图表源码。 |
| SVG 源码、SVG 代码块或网页选区中的 SVG 图形 | 本地 SVG 图片资源。保留常用形状、路径、渐变、文字和静态样式，HTML 图表标签转为 SVG 文字。 |
| 单独一行的 `data:image/svg+xml,...` 地址 | 直接插入本地 SVG 图片，支持 UTF-8 百分号编码和 Base64 地址。 |
| 只含渲染结果的 Mermaid SVG | 静态矢量图。 |
| Graphviz、PlantUML 源码 | 思源图表块。PlantUML 的图像由思源配置的 PlantUML 服务器生成。 |
| Unicode 字符图 | 原代码块和缩进。 |
| 已与截图核对的两段 RAG 图表样式和文字 | 按图表类型和完整标签顺序识别，插入根据截图重建的 Mermaid 流程图或自上而下的思维导图。可同时粘贴两节正文。 |
| 只有 ChatGPT 的 Mermaid 样式和标签文字 | 移除识别出的样式串，保留文字并标明源码缺失。 |

网页控件的点击行为、依赖网页脚本的动画，以及复制时已丢失的图片，需要从原回答另行获取。要保留没有源码的图，可在原回答中复制图片后单独粘贴。

## 如何判断一张图的范围

Mermaid 源码通常在标记为 `mermaid` 的 Markdown 代码围栏内，独立 SVG 则有 `<svg>` 和 `</svg>` 标签。

ChatGPT 把图形复制成纯文本时，样式通常以 `#chatgpt-mermaid-<编号>{` 开始。插件逐条读取同一编号的样式和嵌套规则，跟踪配对的花括号，跳过引号与注释内的括号。最后一条样式之后可能紧跟节点文字。下一张图的起始标记、下一节标题、段落空行或文本末尾可以帮助划分这些文字。不同图的最后一个 CSS 选择器可以不同。只有样式和文字时，连线与父子关系需要另有源码、SVG 或已核对的参考图。

## 验证

`index.js` 是思源直接加载的 CommonJS 入口，无需构建或安装依赖。插件通过思源的粘贴事件提交 Markdown，保存图片、插入内容和撤销都走编辑器自身的流程。
